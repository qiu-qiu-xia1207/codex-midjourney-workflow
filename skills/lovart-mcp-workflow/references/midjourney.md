# 通过 Lovart MCP 调用 Midjourney、回收结果与优化

适用范围：用户已经授权的 Midjourney 图片生成、风格探索、候选比较和后续优化。实际接入由 Lovart MCP 提供，不是直连 Midjourney 官方 API。只检查连接时不执行生成示例。

下文请求形状依据 2026-10-22 可见的 Lovart 工具 schema。执行时重新核对当前工具；历史字段和成功请求不保证未来版本或每个任务成功。

## 1. 确定本轮边界

读取当前项目上下文与已有任务记录，确认用途、目标尺寸或图幅、参考分工、项目 ID、调用上限、是否允许换模型，以及尚未结束的任务。已授权工作继续执行；新增路线、超过预算或用户要求先选样后的扩展，不自动执行。

续作先查原任务 ID。用户打断、等待超时或对话恢复都不是再次生成的理由。若上次已是终态，读存档；若仍 pending，再查询原任务。用户选择等待时保存续作点，不自行安排后台重试。

## 2. 模型与参考图

1. 用 `list_models` 解析用户指定的 Midjourney 路由，再 `describe_model` 读取当前字段。外层 `model` 是 Lovart 路由，`params.model` 才是 Midjourney 版本。
2. 复用用户指定或已返回的 `project_id`；需要查找历史项目时使用 `list_projects`。不传项目 ID 可能新建项目，不能以此绕过原项目问题。

   `list_projects` 可能把项目展示在卡片中，同时结构化 `projects` 为空且 `total` 大于零。先读工具提示；不要仅凭空数组认定没有项目。已有可靠项目 ID 时继续复用，不重复新建或要求用户重选；没有 ID 时再从实际卡片或其他只读结果定位。
3. 实际查看参考图，记录来源、必要的裁切关系、Lovart 托管 URL 和用途。已有同一文件的 Lovart URL 可复用；外部 URL 或本地文件经 `upload_asset` 上传，不把本地路径直接当作模型 URL。
4. `upload_asset` 使用 `filename`、`project_id`，以及 `data_base64` 或 `url` 二选一。在工具编排中直接转交 base64，避免打印到聊天或日志。实际传输上限优先于 schema 提示：曾在 schema 写明本地文件小于 8 MB 时，上传仍被 HTTP 413 拒绝，返回请求体上限为 4,194,304 bytes。此为该次传输限制，不是所有宿主的固定上限。

   上传前估算完整请求体：base64 长度约为原文件的 4/3（准确为 `4 * ceil(原字节数 / 3)`），还须加上 JSON 字段、文件名与其他封装，不能只按原文件大小判断。给实际请求体留余量；超限时保留原件，制作符合用途的压缩副本并检查画面，或采用已获用户授权的托管方式，不临时公开原件。记录格式、质量、像素尺寸是否变化及对应哈希；同题模型比较使用同一压缩副本，避免把输入变化混入模型差异。
5. `image_url` 用于图像／构图／造型引导，`sref` 用于画风。`oref` 仅在当前 schema 和版本支持时按需使用。画风参考不锁定身份；图像引导也不保证对象数量、位置、文字、五官或四肢准确。无需默认从参考图提取数字风格码。造型参考也可能带入源图配色，分开造型与材质参考并不会自动排除颜色影响。若只借形体，明确源图哪些颜色保留、哪些排除；同题模型比较共用目标配色，必要时另给色卡并标明主要部位的颜色，不能只用“多巴胺”等抽象词控制。
6. 比较风格或提示词时记录各路差异。避免无理由同时替换多项输入，使结果无法归因；具体参考数量服从用户要求和当前 schema。当前任务的新视觉参考优先于历史提案；整体画风包含形态、线条、色块组织与情绪，颜色只是其中一部分。用户要求整体风格变化时，不把新参考缩减为对旧形象套历史色卡或仅按部位换色。

## 3. 构造请求并登记

下面只展示请求形状。尖括号内容必须换成当轮实际值，不得直接提交。版本、图幅和其他数值服从用户要求；示例中的历史设置不是通用最佳值。

```json
{
  "project_id": "<当前项目ID>",
  "model": "youchuan/midjourney",
  "prompt": "<本轮完整提示词>",
  "aspect_ratio": "1:1",
  "n": 1,
  "params": {
    "model": "v8.2",
    "mode": "normal",
    "stylize": 100,
    "hd": false,
    "image_url": "<图像参考的Lovart URL；不需要则删除此字段>",
    "sref": "<画风参考的Lovart URL；不需要则删除此字段>"
  }
}
```

- `prompt`、`aspect_ratio`、`n`、`project_id` 等已有顶层字段不在 `params` 重复。其他模型参数按 `describe_model` 原名传入。
- 2026-10-22 的 schema：v8.2 仅支持 normal，draft 仅支持 v7；`iw` 为 0.5–2，`stylize` 为 0–1000 整数，`hd` 只用于 v8.1／v8.2，这两个版本不必传 `render_speed`。执行前重新核对。
- `sw` 不在该次结构化字段中。用户要求且模型支持时，可在提示词使用内联参数，例如历史请求中的 `--sw 100`。没有回显时只记“已请求、未证实”，避免内联参数与结构化参数冲突。
- 提示词写清主体、关系、构图、画法、光线和背景；精确文字、数量或布局列为验收项，不能因提示词写过就视为达成。保留用户要求的质感，不用相反限制抵消它。
- 提交前保存完整请求、时间、调用序号和预算，标记 submitting；返回后立即登记任务 ID、项目 ID、状态、`poll_after_seconds`、回显 spec 和错误。
- 失败也计入用户调用上限；`n=1` 不保证只返回一张，按实际产物计数。并发使用 `get_credits` 返回的 `concurrency_limit`，不硬编码。
- 日常生成服务状态不明时先执行第一个已授权真实任务。不要额外付费“测试登录”，也不要在第一项失败后把剩余额度全部并发提交来试接口。用户明确要求诊断生成故障时，按第7节制定有界隔离序列。

## 4. 查询原任务与展示结果

| 当前情况 | 下一步 |
| --- | --- |
| pending 且有任务 ID | 保存 ID，至少等待 `poll_after_seconds`；需要等待完成或释放并发时使用 `get_task_status`，多个任务合并查询 |
| 等待超时／返回丢失 | 先核对原任务与日志，不直接重发生成；没有 ID 时记录状态未知并诊断 |
| `upload_asset` 返回 HTTP 413／请求体超限 | 记录为上传传输失败；检查 base64 和完整请求体大小，调整副本后再上传。未提交生成时不计入生图调用次数，不据此重新登录 |
| 已取得任务 ID，但本地文件写入／解析报错 | 这不是生成失败证据；从已返回响应或已保存日志恢复原 ID，先修复记录，再查询原任务，不重发生图 |
| completed | 登记全部 artifact ID、URL、格式、实际尺寸和数量，再看图 |
| failed／moderated／not_found | 保存具体错误与终态，不继续轮询终态，不假装已有产物 |

多任务合并响应可能同时含`status=pending`与错误，也可能含`status=completed`、成功产物和错误；这些聚合字段不能代表每个任务的终态。若返回没有逐任务映射，按`poll_after_seconds`等待后，对尚未明确终态的原任务ID分别使用`get_task_status`核实。逐任务保存状态和产物归属，已确认终态的任务移出后续轮询，只继续查询仍pending的任务，不因此重新提交生成。返回的`task_ids`也可能只剩失败或未完成任务；保留提交时登记的完整任务集合，不能用该子集覆盖本轮任务清单或漏掉成功候选。最终展示仍传本轮全部任务ID；这是展示调用，不是继续轮询终态。

生成回合结束，按工具规则用一次 `get_task` 展示提交时登记的本轮全部任务ID并传 `project_id`；需要评图时 `include_images=true`。卡片自行更新，不用 `get_task` 循环轮询；内部等待使用 `get_task_status`。不要漏掉失败任务或较早完成的候选。工具未返回 ID 时不得编造。

单次响应可能只附部分图片预览，以实际图像块及返回提示为准。优先把待评审任务 ID 排在前面；若需要补看，按提示读取缺失任务的预览，最终展示仍保留本轮全部任务。此操作是补充视觉证据，不是终态轮询。`get_task_status` 即使接受 `include_images` 也可能不附图，不能从参数或 URL 推断已经看过画面。

模型列表和 schema 可读、账户只读调用成功，都不能证明生图故障已经恢复。只有真实任务 completed 且返回可查看的产物，才验证了该次生成链路。

## 5. 实际看图后比较

使用工具返回的预览检查，不能从提示词推断画面。逐张记录观察，按实际用途检查主体是否正确、构图、风格、颜色、细节、文字、数量、重复、裁断以及明显生成瑕疵。

模型质量比较须有各模型可查看的实际产物。若一方生成失败、另一方出图，只能分别记录调用成功率与已出图的质量，不能据此宣告后者画面更好；缺少对照的质量比较记为未完成。

比较或筛选多个结果时，按工具规则使用 `rank_candidates_with_jev`。候选描述必须来自实际观察，标准来自用户要求。它依据描述评分，不能替代看图；排名第一也不等于用户选定。保留全部候选及未采用原因。

验收尺度随用途决定。例如，头像或 UI 插图需要在实际显示尺寸检查表情与轮廓；印刷或大幅输出需要核对像素、边缘与材质；系列插图需要并排核对身份与画风。预览通过不等于实际界面已经替换或文件已经交付。

## 6. 根据反馈选择优化方式

| 反馈类型 | 工作方式 |
| --- | --- |
| 整体构图／造型／画风不对 | 保留原候选；明确下一版变量，在授权预算内用 Midjourney 继续探索，不对错误方向持续堆加细节 |
| 方向已选，只需局部修改 | 以选中产物为输入，使用用户已授权且适合精确编辑的模型；先核对其 schema，说明修改区域与保留特征 |
| 已选形象需新场景／姿态／质感 | 复用选中身份基础，按实际用途做小样；对照比例、轮廓、配色和关键特征，不只用 sref 声称身份一致 |
| 用户整批否定或选择等待 | 标记 rejected 或 waiting，保存续作点并停止本轮；不自动重抽、换模型或批量扩展 |

Lovart 的 `edit_image` 当前输入为 `images` 数组，第一张为被编辑图；不是 `ref_images`。`generate_image` 才有 `ref_images`。始终以当前工具 schema 为准，传实际产物 URL 和同一项目 ID。

用户指定系统 imagegen 等其他工具时，按其实际工作流调用并记录独立来源，不能标成 Lovart／Midjourney。用户当前的模型限制优先，历史泛泛允许其他模型不能推翻后来的等待选择。

每次局部编辑集中解决明确问题，并写清须保留的特征。修改后与源图比较，检查非目标区域是否漂移；未通过就保留失败版本，不覆盖母版。透明导出、抠图和放大分别核对实际像素、alpha、边缘与细节，不以文件扩展名或提示词作为完成证据。

## 7. 失败、归档与下一次复用

单任务终态`failed`伴随`API_CALL_ERROR`时，记录该生成任务失败；多任务聚合响应中的错误先按第4节定位到具体任务，不能据此判定整批失败。缺少详情时原因未知，不据此反复登录。日常生成仍在授权预算内且有具体恢复依据，才做至多一次受控重试，尽量只改一个变量；同类错误重复后停止。余额不足时说明限制，不建议购买。

用户明确要求诊断或恢复生成故障时，可在当前授权范围内制定有界隔离序列，记录每步假设、总调用上限和停止条件，失败也计数。固定短提示词、模型和项目，先验证无参考图、无内联附加参数的纯文本请求；成功后每步只添加一个变量，例如先 `sref`，再 `image_url`，必要时再加入内联参数。前一步失败时，只能因下一步能检验另一个明确假设而继续，不能机械耗尽额度。达到上限、没有进一步可区分的假设或用户要求等待时停止。这种测试只用于明确的故障诊断，不作为日常生图前置流程。

隔离测试逐步保存完整请求、提交时间、任务 ID、终态时间和实际产物。“精确重放成功请求”须复用原完整提示词、参考 URL、全部字段和值，包括可选字段的省略状态；只恢复几个参数应称“恢复历史参数组合”。每步成功仅证明该次输入组合在该次调用中可完成，不能反推出先前错误的根因，也不能承诺持续稳定。取得真实任务所需输入组合的成功证据后，在剩余授权预算内转回真实制作，不为补全测试矩阵继续消耗额度；技术完成、画面达标与用户采用仍分别记录。

每轮保留：

- manifest：授权范围／调用上限、提交次数、项目 ID、任务 ID、状态、全部产物、采用状态与续作点。
- 请求与返回：完整提示词、参数、上传 URL／参考分工、回显字段、最终错误或实际输出规格；未回显字段标为“已请求、未证实”。
- 版本：原件、候选和编辑产物分别保存，记录父版本；用户否定的候选不升级为母版。
- 结论：连接成功、任务完成、视觉达标、用户选定、实际应用与导出分别记录，不抹掉历史差异。

原图下载失败单独记录，不改写已完成的生成状态。曾遇到普通 HTTP 客户端返回 403，而带标准 User-Agent 和 Lovart 页面 Referer 的正常下载请求成功；这不是 OAuth 失效证据。只下载用户授权的实际产物，不复制浏览器凭据；记录下载文件的格式与哈希，失败时保留服务端 URL 和续作点。

下一次从项目上下文与当前 manifest 继续，不重走网页登录。只有当前任务确需连接／生成时才执行只读检查；真正认证失败再按 SKILL.md 恢复 OAuth。
