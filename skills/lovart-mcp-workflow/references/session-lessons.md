# 匿名故障案例与可复用经验

本文件将实际使用中观察到的情况归纳为匿名案例，不包含项目资产、账户读数、任务 ID 或原始验证日志。案例说明如何判断故障层次，不保证外部服务永久可用。

## 先区分发生了什么

| 观察 | 可得结论 | 下一步 |
| --- | --- | --- |
| 网页已登录、能看到画布，但当前没有 Lovart 原生工具 | 网页会话可用；尚不能证明 MCP 配置、授权或工具加载有效 | 先发现原生工具，缺失时检查已有配置与宿主加载情况 |
| 项目卡片有内容，但结构化 projects 为空且 total 大于零 | 卡片与结构化列表可能采用不同呈现方式，空数组不证明没有项目 | 阅读工具提示；已有明确项目 ID 时直接复用，不重复新建 |
| 配置已启用，受限环境报告 Auth Unknown | 当前检查结果不确定，不等于用户没有授权 | 在允许的宿主环境检查实际状态，不绕过审批 |
| 状态列表显示 OAuth，但实际连接返回 invalid_grant | 授权记录存在，但刷新令牌被拒绝 | 使用 MCP OAuth 恢复，而非重复安装或反复登录网页 |
| OAuth 恢复后同一对话出现原生工具，账户只读调用成功 | 本次认证与账户访问恢复；该次环境未要求重启整个应用 | 继续当前授权任务；其他版本仍以实际加载状态为准 |
| Midjourney 任务 completed 并返回可查看图片，用户却不满意 | 工具完成与视觉采用是两个不同结果 | 保存全部候选和反馈，不把不满意结果当作母版 |
| 已有任务 ID，最终 failed／API_CALL_ERROR | 请求曾被接收，但生成失败；该错误本身不证明认证失效 | 保存输入和错误，不重复登录，不无依据连续改参数重试 |
| 合并响应同时有pending或completed、错误字段，可能还有部分产物 | 聚合状态不足以判定每个任务成功或失败 | 分别核实尚未明确终态的原任务ID，保留成功产物；只继续查询pending任务，不重发生图 |
| 生成已返回任务 ID，随后本地记录保存报错 | 本地记录故障与远端生成状态不同，不能据此认定请求没有提交 | 从原响应或日志恢复 ID，修复记录并查询原任务，不再次调用生成 |
| 账户、模型目录和 schema 只读查询正常，但没有新生图任务 | 本次账户和 schema 可访问；生图链路是否恢复仍未知 | 不为了验证登录额外付费试图 |
| `upload_asset` 返回 HTTP 413，说明请求体超限 | 上传在传输阶段被拒绝，不是 OAuth 失败，也不是模型生图失败 | 估算 base64 与 JSON 开销，保留原件并制作适用的压缩副本；尚未提交生成就不计入生图调用次数 |

## 曾经耗时的做法

1. **先切换浏览器或使用 computer-use，再检查 MCP。** 原生 MCP 应优先；页面 WebMCP、网站登录和配置的 MCP 是不同入口。
2. **把工具缺失直接解释为用户没登录。** 分开记录网站会话、MCP 授权、工具加载与生成状态。
3. **把 OAuth 状态标记当作有效凭据证明。** 实际只读账户访问才验证该次访问；真正连接错误才支持针对性恢复。
4. **没取得加载故障证据就要求重启整个应用。** 先使用宿主支持的状态查询与恢复能力，重启并非通用必需步骤。
5. **根据通用 API 错误连续更换 HD、权重和提示词。** 没有错误详情或有效对照，不能确定根因。日常重试同类错误重复后停止；用户明确要求诊断时，另按有界、逐变量的隔离序列执行，不无计划地继续抽图。
6. **中断后继续沿用过时的 pending 状态，或重新提交。** 先核对现有任务和已取得的终态，补齐记录再续作。

## 明确故障诊断中的隔离案例

一轮多参考参数的真实任务连续返回通用 API 错误后，用户明确要求诊断。随后采用固定短提示词和同一模型，依次提交纯文本、仅加 `sref`、再加同一参考图的 `image_url`；三步均完成并各返回多个可查看候选。这证明这些输入组合在后续调用时可用，不能证明先前错误由参考图、提示词长度或服务波动中的哪一项造成。

随后保留已成功的参数，仅换成真实角色板提示词，也完成并返回多个候选。实际预览仍有角色数量和网格未满足要求的情况：本次生成路径恢复已获产物证据，但画面验收和用户采用需要另行判断。未重新登录或切换模型家族；省略了若干可选参数的成功请求也不能证明这些参数就是先前根因。

此前一次所谓“恢复基线”只恢复了若干历史参数，同时仍更换提示词和图像输入。它不属于精确重放成功请求。有效对照应保存完整输入并明确唯一改变项；必要时记录提交与终态时间，缺少时间证据时不推断秒退或超时。

隔离序列须有明确授权范围、调用上限与停止条件，不在每次生图前收费测试。验证真实任务所需路径后转回实际制作，并以该任务自己的终态和可查看产物验收；小样成功不能预先替真实任务宣告恢复或交付。

## 多任务合并响应中的混合结果

一次在账户并发限制内提交的三个任务，合并查询先返回`pending`、`API_CALL_ERROR`及“部分仍在生成”的提示；后续逐任务核实为两个completed、一个failed。随后合并终态响应又同时返回`completed`、成功产物与同一错误，且`task_ids`仅包含失败任务。不能据聚合pending重复轮询已结束的任务，不能据错误字段判整批失败，也不能据聚合completed声称全部成功。保存提交时的完整ID集合，分别归档每个任务的终态与产物，仅继续查询仍pending的任务；最终展示包含全部原任务，返回的剩余ID子集不替代完整清单。

## 上传文件大小不等于请求体大小

一次参考图上传中，schema 提示本地文件小于 8 MB，但实际 6,509,821 bytes 的 PNG 经 base64 编码为 8,679,764 个字符后，被 HTTP 413 拒绝；错误明确返回请求体不能超过 4,194,304 bytes。该时账户查询正常，且尚未提交生图，故不能归为 OAuth 失效或生成任务失败，也不增加生图调用次数。

这说明实际传输限制可能低于工具描述中的文件限制。保留原件后，保持 3072×4608 像素尺寸、质量 90 的 JPEG 副本缩至 704,666 bytes，再次 `upload_asset` 成功并返回 Lovart 托管 URL；同轮另一张 506,309 bytes 的 PNG 裁片也上传成功。这仅验证了该次副本上传，不保证后续生成成功。

先估算 base64 的约 4/3 开销及 JSON 封装，给请求体留余量；以符合用途的压缩副本重试。比较不同模型时使用同一副本，记录转换格式、质量、尺寸和哈希，避免输入不同影响判断。错误中的上限仅是该次观察，不能硬编码为所有环境的永久限制。

## 缺失对照与源图配色沿用

一轮两个 Midjourney 请求均返回 API_CALL_ERROR、无产物，而另一个图像工具返回一张图片。这只能证明该轮调用结果不同，不能宣告已出图模型的画面质量胜过未出图模型；质量比较缺少对照，须记为未完成。

该轮还观察到：即使造型与材质参考已分开，生成仍过度沿用造型参考的颜色。一次已授权编辑使用单独色卡并指定部位配色，工具返回了重配色结果，但用户明确否定该版，强调需要整体多巴胺画风并提供新的视觉参考。这仅证明该次编辑返回成功，不代表按部位换色解决了用户目标，也不属于用户采用的风格。

只借形体时应明确源图颜色的保留／排除范围，同题比较使用一致的目标配色；但颜色只是风格的一部分。整体画风还包含形态、线条、色块组织与情绪，不能把新视觉参考缩减为旧品牌色卡换色，也不能仅靠“多巴胺”之类抽象形容词控制。当前任务的新参考优先于历史提案，按用户实际要求重新判断风格目标。

## 参数与结果的证据边界

历史中观察到 `youchuan/midjourney` 请求 `n=1` 仍返回多个候选。应保存实际产物数量，不从 n 推断最终张数。

历史成功任务并未逐项回显全部版本、风格权重、sref 和 HD 设置。请求记录证明参数已发送；schema 证明字段当时可接受；两者都不能单独证明参数实际效果或视觉达标。

小样成功也不保证其他图幅、整板、复杂构图或下一次任务成功。保留成功请求可供有依据的恢复参考，但不能变成所有项目都必须使用的固定参数。

完整执行方式见[Midjourney 提交、结果回收与优化](midjourney.md)。宿主诊断仅在原生工具缺失时按[高级宿主诊断](app-server.md)进行。
