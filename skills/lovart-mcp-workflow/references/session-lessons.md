# 匿名故障案例与可复用经验

本文件将实际使用中观察到的情况归纳为匿名案例，不包含项目资产、账户读数、任务 ID 或原始验证日志。案例说明如何判断故障层次，不保证外部服务永久可用。

## 先区分发生了什么

| 观察 | 可得结论 | 下一步 |
| --- | --- | --- |
| 网页已登录、能看到画布，但当前没有 Lovart 原生工具 | 网页会话可用；尚不能证明 MCP 配置、授权或工具加载有效 | 先发现原生工具，缺失时检查已有配置与宿主加载情况 |
| 配置已启用，受限环境报告 Auth Unknown | 当前检查结果不确定，不等于用户没有授权 | 在允许的宿主环境检查实际状态，不绕过审批 |
| 状态列表显示 OAuth，但实际连接返回 invalid_grant | 授权记录存在，但刷新令牌被拒绝 | 使用 MCP OAuth 恢复，而非重复安装或反复登录网页 |
| OAuth 恢复后同一对话出现原生工具，账户只读调用成功 | 本次认证与账户访问恢复；该次环境未要求重启整个应用 | 继续当前授权任务；其他版本仍以实际加载状态为准 |
| Midjourney 任务 completed 并返回可查看图片，用户却不满意 | 工具完成与视觉采用是两个不同结果 | 保存全部候选和反馈，不把不满意结果当作母版 |
| 已有任务 ID，最终 failed／API_CALL_ERROR | 请求曾被接收，但生成失败；该错误本身不证明认证失效 | 保存输入和错误，不重复登录，不无依据连续改参数重试 |
| 账户、模型目录和 schema 只读查询正常，但没有新生图任务 | 本次账户和 schema 可访问；生图链路是否恢复仍未知 | 不为了验证登录额外付费试图 |

## 曾经耗时的做法

1. **先切换浏览器或使用 computer-use，再检查 MCP。** 原生 MCP 应优先；页面 WebMCP、网站登录和配置的 MCP 是不同入口。
2. **把工具缺失直接解释为用户没登录。** 分开记录网站会话、MCP 授权、工具加载与生成状态。
3. **把 OAuth 状态标记当作有效凭据证明。** 实际只读账户访问才验证该次访问；真正连接错误才支持针对性恢复。
4. **没取得加载故障证据就要求重启整个应用。** 先使用宿主支持的状态查询与恢复能力，重启并非通用必需步骤。
5. **根据通用 API 错误连续更换 HD、权重和提示词。** 没有错误详情或有效对照，不能确定根因。每次重试计入预算，同类错误重复后停止。
6. **中断后继续沿用过时的 pending 状态，或重新提交。** 先核对现有任务和已取得的终态，补齐记录再续作。

## 参数与结果的证据边界

历史中观察到 `youchuan/midjourney` 请求 `n=1` 仍返回多个候选。应保存实际产物数量，不从 n 推断最终张数。

历史成功任务并未逐项回显全部版本、风格权重、sref 和 HD 设置。请求记录证明参数已发送；schema 证明字段当时可接受；两者都不能单独证明参数实际效果或视觉达标。

小样成功也不保证其他图幅、整板、复杂构图或下一次任务成功。保留成功请求可供有依据的恢复参考，但不能变成所有项目都必须使用的固定参数。

完整执行方式见[Midjourney 提交、结果回收与优化](midjourney.md)。宿主诊断仅在原生工具缺失时按[高级宿主诊断](app-server.md)进行。
